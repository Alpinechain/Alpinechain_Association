# Prompt — Cadrage événement AlpineChain

Version : V1.0  
Dernière mise à jour : 2026-07-11

## Rôle du prompt

Ce prompt sert à cadrer un événement AlpineChain avant toute production de contenu. Le résultat doit être consolidé dans une Issue créée avec le modèle `.github/ISSUE_TEMPLATE/evenement.md`.

Référence opérationnelle : [`references/event-standard.md`](../references/event-standard.md)

Il doit être utilisé avant de demander :

- un article ;
- une annonce Meetup ;
- des posts réseaux sociaux ;
- un visuel ;
- un compte-rendu ;
- une séquence de relance.

## Prompt à copier-coller

```text
Projet : AlpineChain Association
Rôle attendu : coordinateur événement + analyste éditorial

Objectif : cadrer un événement AlpineChain avant production et publication.

Type d’événement : [Atelier Bitcoin / Souveraineté 3.0 / Beer2Beer / Micro-projet]
Date : [YYYY-MM-DD ou à définir]
Horaire : [horaire Europe/Paris]
Lieu : [lieu ou à définir]
Responsable opérationnel : [nom]
Lien d’inscription : [lien ou décision sans inscription]
Thème : [thème]
Public cible : [public]
Niveau requis : [débutant / intermédiaire / avancé / ouvert à tous]
Format : [atelier pratique / discussion / table ronde / démonstration / autre]
Intervenants : [noms si connus]
Capacité : [nombre]
Tarif : [montant ou gratuit]
Budget maximal : [montant]
Contexte utile : [éléments déjà validés]
Contraintes : [durée, ton, ressources obligatoires, éléments à éviter]

Avant de produire quoi que ce soit :
1. reformule l’objectif de l’événement ;
2. formule la promesse publique en une phrase ;
3. identifie le CTA ;
4. vérifie la porte de lancement : date, lieu, responsable, public, format, inscription et budget ;
5. liste les ambiguïtés, dépendances et risques ;
6. propose les livrables nécessaires ;
7. prépare la checklist J-21 / J-14 / J-10 / J-7 / J-3 / J-1 / J / J+1 / J+3 ;
8. indique ce qui exige une validation humaine ;
9. vérifie la cohérence avec AlpineChain : pédagogie, souveraineté numérique, outils ouverts, ancrage local et absence de promesse spéculative.

Sortie attendue :
- bloc Identité prêt à coller dans l’Issue ;
- objectif et promesse ;
- décisions acquises et manquantes ;
- angle éditorial et messages clés ;
- CTA ;
- checklist datée lorsque la date est connue ;
- risques et plan de repli ;
- liens et emplacements documentaires ;
- points de validation humaine.
```

## Definition of Done

Le cadrage est terminé quand :

```text
[ ] le type d’événement est clair ;
[ ] la date, le lieu et le responsable sont définis ou explicitement marqués comme bloquants ;
[ ] le public cible et le niveau sont définis ;
[ ] la promesse publique est formulée ;
[ ] le CTA et l’inscription sont identifiés ;
[ ] le budget ou l’enveloppe maximale est connu ;
[ ] les risques, dépendances et plans de repli sont listés ;
[ ] la checklist J-21 à J+3 est prête ;
[ ] les livrables à produire sont connus ;
[ ] la validation humaine reste prévue avant publication.
```
