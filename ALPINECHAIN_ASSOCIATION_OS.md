## 1. Objet du document

Ce document sert de base de pilotage pour les activités associatives AlpineChain.

Il doit rester court, lisible et actionnable.

Il sert à cadrer :

- la communication associative ;
- l’animation des formats récurrents ;
- la production de contenus ;
- la capitalisation après événement ;
- l’usage de l’IA dans le cadre AlpineChain ;
- la structure future du projet documentaire.

Règle de base : ce fichier est une boussole, pas une encyclopédie.

---

## 2. Positionnement associatif

AlpineChain est une association locale dédiée à Bitcoin, à la souveraineté numérique, aux outils ouverts et à l’expérimentation territoriale dans les Alpes.

Axes à renforcer :

- Bitcoin ;
- souveraineté numérique ;
- logiciels libres et open source ;
- vie privée ;
- Nostr ;
- auto-hébergement ;
- économie monétaire ;
- infrastructures ouvertes ;
- éducation populaire ;
- expérimentation locale.

Axes à réduire :

- web3 comme bannière principale ;
- crypto générique ;
- blockchain fourre-tout ;
- innovation vague ;
- discours spéculatif.

Le mot `web3` peut rester un sujet d’analyse ou de discussion, mais il ne doit plus piloter l’identité publique AlpineChain.

## 4. Publics cibles

Publics prioritaires :

- curieux de Bitcoin ;
- utilisateurs souhaitant progresser vers plus d’autonomie ;
- membres AlpineChain ;
- commerçants, indépendants et entrepreneurs locaux ;
- développeurs, makers, profils open source ;
- personnes sensibles à la souveraineté numérique ;
- acteurs locaux : écoles, tiers-lieux, associations, entreprises, institutions.

Principe : rester accessible par défaut, technique quand nécessaire.

---

## 5. Ligne éditoriale

Promesse publique :

> Apprendre, pratiquer, comprendre et construire localement autour de Bitcoin et de la souveraineté numérique.

Ton recherché :

- local ;
- clair ;
- pédagogique ;
- non spéculatif ;
- non corporate ;
- non partisan ;
- concret ;
- ouvert à la discussion.

À éviter :

- jargon inutile ;
- promesses financières ;
- posture gourou ;
- communication sans appel à l’action ;
- confusion entre hypothèse, opinion et décision validée.

## 7. Workflow mensuel de production

### J-21 — Cadrage

- définir le thème ;
- préciser le public cible ;
- formuler la promesse ;
- identifier le CTA ;
- lister les ressources utiles ;
- décider des canaux à activer.

### J-14 — Production principale

- article blog ou page événement ;
- description Meetup ;
- texte Pretix si nécessaire ;
- visuel principal ;
- posts réseaux sociaux.

### J-7 / J-3 / J-1 — Relance

- rappels courts ;
- angle différent par canal ;
- CTA clair ;
- vérification des liens.

### J+1 / J+3 — Capitalisation

- compte-rendu ;
- questions posées ;
- ressources partagées ;
- photos ou supports ;
- points d’amélioration ;
- prochaine action.

## 8. Rôles IA autorisés

| Rôle IA | Mission |
|---|---|
| Agent coordinateur | Faire respecter les règles du système IA, la structure du dépôt, le périmètre AlpineChain et la cohérence entre les fichiers |
| Analyste | Clarifier objectif, public, angle et contraintes |
| Rédacteur | Produire articles, posts, descriptions et annonces |
| Reviewer | Vérifier cohérence, ton, clarté, CTA et respect du cadrage |
| Documentaliste | Produire comptes-rendus, fiches pratiques et synthèses |
| Planificateur | Préparer calendrier éditorial et séquences mensuelles |
| Contradicteur | Détecter flou, jargon, promesse faible, hypothèses déguisées en décisions |

Usage interdit de l’IA :

- publier automatiquement ;
- parler au nom du bureau sans validation ;
- inventer des décisions associatives ;
- transformer AlpineChain en canal commercial ;
- présenter une hypothèse comme une décision validée.

Rôle des dossiers :

| Emplacement | Rôle |
|---|---|
| `AGENTS.md` | Instructions données aux agents IA travaillant sur le projet |
| `docs/` | Documents principaux de pilotage |
| `docs/journal-progression/` | Suivi structuré des avancées du système |
| `notes/hebdo/` | Notes courtes de suivi hebdomadaire |
| `notes/mensuel/` | Revue mensuelle et décisions à consolider |
| `templates/` | Prompts et checklists réutilisables |
| `assets/` | Index des visuels, exports et ressources stockées ailleurs, notamment Nextcloud |

Principe : GitHub porte la méthode et l’historique. Nextcloud porte les fichiers lourds et les visuels.
