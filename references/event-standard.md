# Standard événement AlpineChain

Version : V1.0  
Dernière mise à jour : 2026-07-11

## Objet

Ce document définit le modèle opérationnel commun aux événements AlpineChain : ateliers Bitcoin, rendez-vous Souveraineté 3.0, Beer2Beer et rencontres associatives.

B-Only utilise les mêmes règles de responsabilité, d’échéance, de validation et de capitalisation, mais son pilotage est découpé en plusieurs chantiers.

## Principe directeur

```text
Un événement = une Issue principale = un responsable = une date de référence.
```

L’Issue reste ouverte jusqu’à la capitalisation J+3. Une publication publique ne vaut jamais validation opérationnelle.

## Données obligatoires

Chaque Issue événement doit préciser :

- le projet concerné ;
- le titre public ou le thème de travail ;
- la date, l’horaire et le fuseau `Europe/Paris` ;
- le lieu ou le format distant ;
- le responsable opérationnel ;
- le public cible et le niveau attendu ;
- la promesse publique ;
- le format et les intervenants ;
- le lien d’inscription et le CTA ;
- la capacité et le tarif éventuel ;
- les dépendances, risques et validations humaines ;
- les emplacements documentaires et liens publics.

## Porte de lancement

Le compte à rebours J-21 ne commence que lorsque les éléments suivants sont décidés :

- [ ] date et horaire ;
- [ ] lieu ou solution distante ;
- [ ] responsable opérationnel ;
- [ ] thème et promesse ;
- [ ] public cible et niveau ;
- [ ] format et intervenant principal, si nécessaire ;
- [ ] capacité et conditions d’accès ;
- [ ] lien d’inscription ou décision explicite de ne pas en utiliser ;
- [ ] budget ou enveloppe maximale ;
- [ ] validation humaine du lancement.

Tant que cette porte n’est pas franchie, l’Issue reste en cadrage et les dates relatives sont indiquées `à calculer`.

## Checklist standard J-21 à J+3

Les tâches marquées « si pertinent » peuvent être écartées explicitement. Elles ne doivent pas disparaître silencieusement.

### J-21 — Cadrage et mise en production

- [ ] Verrouiller le brief : objectif, promesse, public, niveau, format et CTA.
- [ ] Confirmer le responsable et les contributeurs.
- [ ] Confirmer le lieu, la capacité, les accès et les contraintes.
- [ ] Créer ou vérifier la page d’inscription.
- [ ] Définir le plan éditorial et les livrables.
- [ ] Commander ou produire le visuel principal.
- [ ] Identifier le matériel, les logiciels, les supports et les achats.
- [ ] Lister les dépendances, risques et plans de repli.
- [ ] Ajouter les liens GitHub, Nextcloud, Pretix, Meetup et site.
- [ ] Obtenir la validation humaine avant publication.

### J-14 — Publication principale

- [ ] Publier ou programmer la page événement, Meetup et inscription.
- [ ] Publier l’annonce principale sur les canaux retenus.
- [ ] Vérifier date, horaire, lieu, tarif, niveau, CTA et tous les liens.
- [ ] Confirmer l’intervenant, le titre, la biographie et les droits d’image.
- [ ] Vérifier que l’événement apparaît dans les calendriers utiles.
- [ ] Archiver les URLs des publications dans l’Issue.

### J-10 — Relance pédagogique

- [ ] Publier un contenu expliquant le problème traité ou le bénéfice concret.
- [ ] Rappeler les prérequis, le niveau et le matériel attendu.
- [ ] Vérifier le rythme des inscriptions et adapter la diffusion.
- [ ] Confirmer les ressources pédagogiques ou documentaires.

### J-7 — Revue opérationnelle

- [ ] Confirmer le lieu, l’accueil, les horaires et les contacts sur place.
- [ ] Confirmer l’intervenant et le conducteur.
- [ ] Tester le matériel, les logiciels et les comptes nécessaires.
- [ ] Vérifier la liste des inscrits et la capacité restante.
- [ ] Publier une relance orientée bénéfice ou cas d’usage.
- [ ] Affecter les rôles du jour J.

### J-3 — Informations pratiques

- [ ] Effectuer le test technique final.
- [ ] Confirmer le nombre de participants attendu.
- [ ] Préparer les listes, badges, signalétique ou feuilles de présence, si pertinent.
- [ ] Préparer les supports, sauvegardes et solutions hors ligne.
- [ ] Publier le rappel pratique : date, heure, lieu, accès, niveau et matériel.
- [ ] Vérifier le plan de repli et les numéros utiles.

### J-1 — Dernier contrôle

- [ ] Envoyer ou publier le dernier rappel.
- [ ] Vérifier le conducteur minute par minute.
- [ ] Charger, imprimer ou synchroniser les supports nécessaires.
- [ ] Vérifier les moyens de paiement et dépenses prévues, si pertinent.
- [ ] Confirmer les clés, accès, transports et responsabilités.
- [ ] Vérifier les autorisations photo, vidéo ou diffusion.

### J — Exécution

- [ ] Ouvrir et préparer le lieu.
- [ ] Accueillir les participants et traiter les inscriptions de dernière minute.
- [ ] Respecter le conducteur et tracer les écarts importants.
- [ ] Collecter les questions, incidents, dépenses et décisions.
- [ ] Prendre les photos ou captations autorisées.
- [ ] Annoncer les ressources et la prochaine étape.
- [ ] Fermer le lieu et sécuriser matériel, données et paiements.

### J+1 — Remerciements et ressources

- [ ] Remercier participants, intervenants, lieu et partenaires.
- [ ] Partager les ressources promises.
- [ ] Renseigner le nombre d’inscrits, présents et absents.
- [ ] Consolider les dépenses, recettes et incidents.
- [ ] Trier et archiver les photos, supports et documents.
- [ ] Signaler immédiatement les suites urgentes.

### J+3 — Capitalisation et clôture

- [ ] Publier ou archiver le compte-rendu.
- [ ] Documenter les questions, retours et décisions utiles.
- [ ] Mesurer inscriptions, présence, conversion et engagement.
- [ ] Identifier trois points réussis et trois améliorations.
- [ ] Créer les Issues de suivi nécessaires.
- [ ] Mettre à jour les modèles ou procédures si une amélioration est récurrente.
- [ ] Vérifier l’archivage Nextcloud et les liens publics.
- [ ] Fermer l’Issue lorsque la Definition of Done est atteinte.

## Sources de vérité

| Sujet | Outil principal |
|---|---|
| Actions, décisions, risques et responsables | GitHub Issue |
| Vue portefeuille et échéances | GitHub Project |
| Inscriptions et participants | Pretix ou outil indiqué dans l’Issue |
| Documents, visuels, photos et supports | Nextcloud |
| Publications publiques | Site, Meetup et réseaux concernés |
| Contacts, devis et factures | Dolibarr |
| Comptabilité | Paheko |

Les données personnelles et commerciales détaillées ne doivent pas être recopiées dans GitHub.

## Indicateurs minimaux

Après l’événement, renseigner au minimum :

- inscriptions ;
- présents ;
- taux de présence ;
- nouveaux participants, lorsque mesurable ;
- recettes et dépenses, si pertinent ;
- incidents ou écarts ;
- retours qualitatifs ;
- prochaine action.

## Definition of Done

L’Issue peut être fermée lorsque :

- [ ] l’événement a été réalisé ou annulé avec une décision documentée ;
- [ ] les ressources promises ont été partagées ;
- [ ] les indicateurs minimaux sont renseignés ;
- [ ] les dépenses et recettes sont transmises aux outils concernés ;
- [ ] les documents sont archivés ;
- [ ] les actions de suivi ont leur propre Issue ;
- [ ] la capitalisation J+3 est terminée.
